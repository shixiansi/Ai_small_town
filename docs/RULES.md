## 1. 项目结构与工具链

```
office/
  web/src/*.js          ← 源码片段（office.js 由它们拼装）
  web/office.js         ← 构建产物，禁止手改
  web/map.json          ← 地图数据（家具/区域/墙/路/阻挡）
  hub/map.custom.json   ← 编辑器自定义层（floor/terrain/hide/light/shadow/move + 家具）
  tools/                ← 全部零依赖 Node 脚本
```

### 命令（每次改完 `web/src/*` 或 `web/map.json` 都要跑前三条）

```bash
node tools/build.mjs            # 拼装 web/office.js
node tools/bust.mjs             # 重写内容哈希版本号（index.html / boot.js 里的 ?v=）
node tools/check.mjs            # 32 项门禁；必须 "0 个错误"
```

**铁律：`bust` 必须在 `check` 之前跑。** 改了 `map.json` 不跑 `bust`，`check` 会在"版本号过期"上失败
—— 这是**假阴性**，会让人误判成几何问题（见 §8 坑 1）。

### 改坐标只用这一个工具

```bash
node tools/place.mjs --id=ofFile2 --cell=11,28           # 预览：占格/贴墙/叠件/占锚点/压路
node tools/place.mjs --id=ofFile2 --cell=11,28 --apply   # 落盘
node tools/place.mjs --id=desk --cell=9,21 --anchor=desk:9,19.2 --apply
node tools/place.mjs --list --room=office                # 每件占格 + 跨列警告
node tools/room-ascii.mjs --room=office                  # 带标尺的房间图纸
```

**不要手写 x/y 小数。** `place.mjs` 用 `cellsOf` 反解坐标：你只说"要占哪一格"，
它负责满足 x 取整、y 取 `row+0.25` —— 这两个约定是被三套判据同时逼出来的，见 §2。

## 2. 唯一事实源：`tools/map-model.mjs`

**所有工具都必须 import 它，不允许各自实现一套。** 这条以前只是口号，第 41 轮才真正做到：
`check.mjs` / `map-audit.mjs` / `facing-check.mjs` / `layout-audit.mjs` 四家各自复刻过一遍
"家具占哪些格"，**四套结果互不相同**，代价见 §8 坑 2。

```js
import { loadModel } from "./map-model.mjs";
const model = loadModel();
// model.items / solid(f) / cellsOf(f) / isBlocked(x,y) / rooms / roomOf(x,y)
// model.anchorCells / roadCells / anchors / conflictsOf(f) / protectedSet
// model.wallCells / wallTouch(f) / touchesWall(f)          ← 墙格与"贴墙"的唯一实现
```

`parityWithCheck(model)` 把模型的判断和 `check.mjs` 的实际判定逐条对账 —— **改动模型后必须跑，35 个锚点要全一致**。

### 取整 / 落位口径（踩过很多次的坑，别自己发明）

| 用途 | 口径 |
|---|---|
| 家具占格 | 与运行时 `furniture.js buildBlockedGrid` 逐字同算式，**只有 `cellsOf()` 一份** |
| 横向坐标 `f.x` | **必须是整数**。运行时 `p.x = f.x*TILE + TILE/2`，非整数会让贴图压在格线上、同时占两列 |
| 纵向坐标 `f.y` | 取 `目标行 + 0.25`。这样脚底行 = 目标行，且 `map-audit` 的 `floor(f.y)` 也 = 目标行 |
| 锚点格 | `Math.round`（不是 floor） |
| 房间归属 | `Math.floor(x), Math.floor(y)`（与 `map-audit` 的 H3 一致） |

**占格算式必须连 `band`（贴顶部墙带）和 `bboxRows`（按 `frame` 取朝向那一行的 bbox）一起复刻**，
漏一个就会出现"算着不压锚点、门禁说压了"。第 41 轮前的实测差异：
模型漏了 `TILE/2` 中心偏移 → 每件家具往左上偏半格；`check.mjs` 漏了竖墙的 `y/h` → x=10/16/25
三列在**整张图**上凭空不可走；`map-audit` 又抄了第三份不同的 floor 口径。

## 3. 数据模型

### `web/map.json`

```jsonc
{
  "room": { "tile": 48, "cols": 56, "rows": 30, "wallH": 48 },
  "furniture": [
    { "a": "office-desk", "x": 9, "y": 21.25, "id": "desk",
      "o": 1,        // 装饰：不占碰撞
      "wall": 1,     // 挂墙：不占地面碰撞
      "on": "desk",  // 叠加在 host 上：不占碰撞，且没有自己的 x/y（跟随 host）
      "band": 1,     // 贴顶部墙带：脚点落在 48px 墙带底边，不按 y 换行
      "sc": 1.3,     // 缩放（注意：运行时碰撞**不算** sc）
      "flipX": 1     // 水平镜像（唯一可用的"朝向"手段）
    }
  ],
  "zones": { "desk": { "anchor": [9, 19.2], "host": "desk", "sit": { "host": "chairA" } } },
  "walls": [ { "x": 10, "y": 1, "h": 14, "gap": [5, 7] } ],   // 竖墙带 x/y/h；横墙带 y/x0/x1
  "roads": [ { "x": 26, "y": 16, "w": 30, "h": 3 } ],
  "blockers": { "pond": { ... } }
}
```

**每件家具必须有 `id`**（当前全部有）。没有 id 就无法"改一件、验一件、坏了只回退这一件"。

### `hub/map.custom.json`（编辑器层，会在渲染时叠加）

| `a` 值 | 含义 |
|---|---|
| `floor` `{t:"wood\|tile\|grass\|stone\|road"}` | 逐格改写地板 |
| `terrain` `{t:"wall\|water"}` | 逐格叠地形，**同时不可走** |
| 其他素材名 | 追加家具（与 base 同构；id 形如 `cumw9xxx`） |
| `hide` `{k:"flowers@17.2,10.8"}` | 隐藏指定家具 |
| `light` `{r,a,tint,room}` | 灯池（第 3 层光照） |
| `shadow` `{id,x,y,w,h,night,lit,day}` / `del:1` | 房间级阴影块 / 删除内置块 |
| `move` `{k:"id:xxx"}` | 移动 base 里的家具 |

**注意**：这层能盖掉 base 的一切。曾经 9 格刷出来的墙堵死办公室东出口、379 格地板刷盖掉草坪 ——
而只看 `map.json` 的审计完全看不出来。`map-model` 已经把它并进来，别再绕过去。

**这层可以当普通文件改**（`place.mjs` 落位、脚本批量改都行），v87 起 hub 会按 mtime 跟磁盘对账，
改完 1.5s 内广播热重载，**不需要重启 hub**。两个写入者（hub 与磁盘）都在时，
hub 是"照磁盘走"的那一方：**读之前、写之前都会先同步磁盘**，
所以不会再出现"改了文件没反应"或"下一次编辑器保存把文件改动写回去"。
（见 §8 坑 11 —— 这个毛病曾经反复发作，根源就是 hub 只在启动时读过一次。）

| # | 维度 | 工具 | 判据 |

## 5. 硬规则（违反就会好看不了）

### 5.1 贴墙 ≠ 站在墙上（第 41 轮已修正）

```
错：背靠墙 = 上下左右 1 格内有墙        ← "自己就在墙格上"也成立 → 家具被推进墙里
对：背靠墙 = 与墙相邻 且 本格不是墙
```

现在是 `map-model.wallTouch(f)` 的**三态**返回值，别再自己写布尔判断：

| 返回 | 含义 | 处理 |
|---|---|---|
| `"ok"` | 占格都不是墙，且至少一格四邻有墙 | 合格 |
| `"on-wall"` | 有占格本身是墙 → 家具被推进墙里 | 必须挪（`facing-check` 单独报这一条） |
| `"none"` | 不挨墙 | R1/R2 违规 |

判定必须走 `cellsOf`（整片占格），不能只看 `round(f.x),round(f.y)` 一格 —— 宽体家具靠墙那一格
挨着墙时，只看一格会**反向漏判**。墙格也统一到 `model.wallCells`（第 0 行墙带 + `mapdata.walls`
+ 自定义地形墙 + `room.js` 外墙裙四者合一），那份墙集合以前被抄了四遍。

### 5.2 锚点 = host + 朝向 1.2 格

`zones[*].anchor` 不靠几何猜，靠 `zones[*].host`（家具 id）推导：

```
anchor = host 位置 + 朝房间内侧 1.2 格，且必须可走（isBlocked=false）
```

`tools/anchor-from-host.mjs` 已实现。**已通过门禁的锚点不要动**；
但**挪了 host 就必须同步挪 anchor**，否则门禁的"区域语义：期望家具在 2.2 格内"会立刻现形
（第 41 轮冰箱从 row2 挪到 row1 后，`fridge` 锚点就必须跟着从 [17.5,4] 走到 [17,2.2]）。

### 5.3 朝向规则（只有这四条可判定，其余一律不算错）

| 规则 | 适用 | 要求 |
|---|---|---|
| R1 背靠墙 | 柜 / 书架 / 文件柜 / 衣柜 / 马桶 / 洗手盆 / 灶台 / 操作台 / 储物柜 | 与墙相邻且不在墙格 |
| R2 头靠墙 | 床 / 双人床 | 同上 |
| R3 面桌 | 椅子 / 办公椅 | 2 格内必须有桌（table/round-table/dining-table/office-desk/desk-wood/**school-desk**） |
| R4 面茶几 | 沙发 / 单人沙发 | 2.5 格内必须有茶几（round-table/dining-table） |

**上下朝向做不到**：74 个素材都是单朝向，`flipX` 只能表达"朝左/朝右"。要上下朝向必须补美术，别假装实现。

**R3 的桌子白名单要跟素材同步**：`school-desk` 也是桌，漏掉它会误报两张书桌椅（第 41 轮踩过）。
**R4 只认茶几不认书桌**：书房里一张单人沙发旁边只有书桌时，正确解法是补一张 `round-table`，
不是放宽规则。

### 5.4 房间布局的两层结构

```
y = 室内首行        ← 家具本体（贴墙那一排）
y = 室内首行 + 1.2  ← 锚点/站立位（鱼站这儿）
y = 中间            ← 2 格宽动线，不许放东西
```

**"家具贴墙"与"锚点要可站"是同一块地**，必须联合求解；分开做必然互相打架。
第 41 轮的 office 就是按这个做的：北墙一排储物、南墙一排茶水/街机/文件柜、
中间 y=21 一条工位、左右两个休息角。

### 5.5 布局四指标（`layout-audit.mjs`）

```
贴墙率 ≥50%（大件靠墙）· 最近邻中位 ≤3.2（成组而非散点）
最长空段 ≤6 格 · 对齐率 ≥35%（成排）
```

**"最长空段 ≤6" 是密度指标，不是审美指标。** 第 41 轮实测：
bath（6 格宽 / 10 件）、kitchen（9 格宽 / 25 件）、nbChief（5 格宽 / 9 件）都能做到 6；
office（26 格宽 / 47 件）做不到 —— 要每行至少 4 件才能把 24 格净宽切成 ≤6 的段，
13 行就是 52 件起步，而列方向也要满足。bedroom（9 格宽 / 22 件）差 8 件。
再往上加就是**为了凑数字摆成地毯**，那正是这个指标本来要防的东西。

所以用法是：
1. 四指标全绿的房间（bath / kitchen / nbChief）**别再动**；
2. 没绿的看**趋势**（每次改布局必须变小），并看它报的位置（`19 格(y=24)` = 第 24 行最空），照着那一行补东西；
3. 补齐到"再加就难看"为止，剩下差额写进 §9 未完成，不要偷偷调阈值。

判据顺序：**实拍图看"像不像人摆的" → 四指标看趋势 → 门禁看底线**。

### 5.6 逐件阴影 = 接触阴影，不许复制本体贴图（`shadow-audit.mjs` 守着）

```
椭圆（s.add.ellipse）· 宽 = 内容宽 × 缩放 × 1.08 · 高 = clamp(6, 6+内容高/16, 14)
颜色 0x241a12 · alpha 0.26 · 偏移 +2/+3 px（全局光向，与房间级阴影同侧）
depth = 本体 - 1 · 只给 !o && !wall && !on 的件加 · 必须登记到 p.shadow（重建才销毁得掉）
```

**反向断言（曾经错的地方）**：不许再出现"把家具贴图再画一遍、`setTint(0x000000)`、斜移 +6/+10"的写法。
那一版阴影里带着物品的全部细节（镂空、亮面、描边），看着是**物体被复制了一份**而不是地面投影；
而且那份 image 没有登记到任何地方，每次重建家具层都多叠一层黑影子。

> 教训：`shadow-audit.mjs` 旧版逐条断言了 `add.image 剪影` / `tint 0x000000` / `+6/+10` ——
> **门禁把一个错误的实现锁成了"规格"**，于是谁都不能改。现在同时有正向（接触阴影的规格）
> 和反向（别再把复制贴图写回来）断言，而且断言只看代码、不看注释。

房间级阴影是另一套（`mapedit.js`）：`{ night: 0.60, lit: 0.15, day: 0.00 }`，**白天浓度就是 0**，
别在白天截图里找房间阴影。

## 6. 逐件作业规程（必须遵守）

```bash
node tools/place.mjs --id=<id> --cell=<x>,<row>            # 1) 先预览，它会当场报贴墙/叠件/压锚点/压路
node tools/place.mjs --id=<id> --cell=<x>,<row> --apply    # 2) 落盘
node tools/bust.mjs                                        # 3) 版本号（不跑就是假阴性）
node tools/check.mjs                                       # 4) 0 错误才继续
node tools/facing-check.mjs --room=<房>                     # 5) 判"这一件"的违规消失
```

不通过 → **只回退这一件**，记录原因，继续下一件。

**禁止批量改**：一批一起动，只要 1 个坏，整批作废，而且看不出是哪个。
但"成组件"（桌子 + 椅子 + 锚点）必须**一起**改 —— 它们互相定义对方的合法性。

## 8. 已知的坑（都踩过，别再踩）

| # | 坑 | 表现 | 对策 |
|---|---|---|---|
| 1 | 版本号污染判据 | 每次改动后 `check` 报"版本号过期"，被误判为几何错 | 判门禁前先 `bust` |
| 2 | **占格口径分叉** | 四套实现各差半格：宽体靠墙判失败／x=10/16/25 三列凭空不可走／报"踩在墙上""路断了"／真压路的看不见 | 只认 `map-model.cellsOf`，其余工具一律 import，不许自己算 |
| 3 | `f.x` 非整数 | 贴图压在格线上，运行时同时占两列；`place.mjs` 会警告 | 一律 `x` 取整、`y = row + 0.25` |
| 4 | 自定义层隐形 | 只看 `map.json`，画面完全不同 | 一律用 `map-model`（已并层） |
| 5 | 批量改锚点 | 一处坏，整批废，且定位不到 | 逐件改、逐件验、单件回退 |
| 6 | "站墙上"当"贴墙" | 家具被推进墙格，警告增加 | `wallTouch` 三态，"on-wall" 单独报 |
| 7 | 无 id 的家具 | 无法精确回退，只能整批回滚 | 全部有 id |
