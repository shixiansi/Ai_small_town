# 地图与摆放：成熟 2D 小镇游戏的通行模型

> 这份文档回答一个问题：**为什么"手调坐标"必然失败，以及成熟做法是什么。**
> 上一轮（第 42→43 轮）反复出现"果盘摆在地上""户外摆设进屋"这类问题，
> 根因不是某个坐标写错了，而是整个摆放模型建在不可靠的基础上。

---

## 0. 一句话

**位置由规则推导，不由人手填写。** 手填的每一个像素偏移，都是一次没有判据的猜测。

---

## 1. 本轮之前的结构性问题（有数据）

把 70 个素材逐个量一遍，结果是这样：

```
70 个素材里，68 个的 frame 尺寸或 bbox 宽度不在 48px 网格上
  路灯   bbox 宽  8px = 0.17 格
  餐桌   bbox 宽 58px = 1.21 格
  橡树   bbox 宽 96px = 2.00 格
```

旧模型的三处硬伤：

| 问题 | 后果 |
|---|---|
| 碰撞格由 `bbox` 反推（`floor((py-WALL_H-1)/T)`） | 每件素材的格子数都不一样，出现 0.17 格、1.21 格这种碎片 |
| 桌上物品的落点靠手写 `dx/dy` | 漏写 → 贴到宿主顶边（悬空）；猜错 → 沉进桌面或压到别的东西上 |
| 手写 `dx/dy` 与美术不联动 | 换一张桌子、换一件物品，之前的数字全部失效 |

**果盘那次的完整链条**：`on` 缺失 → 补 `on` 但没补 `dx/dy` → 贴顶边悬空 →
补 `dx=-15` 但没算桌面高度 → 压到笔记本上 → 几何门禁全绿，画面全错。

## 2. 成熟做法（Tiled / RPG Maker / Stardew 一脉）

### 2.1 三层分离

```
逻辑层：格子（48×48）—— 占格、碰撞、可走性全部只认整数格
美术层：贴图 —— 允许向上溢出（树冠、高柜），不参与逻辑
摆放层：墙上 / 桌上 / 地上 —— 由素材属性决定，不由摆放者临时决定
```

### 2.2 四个"唯一事实源"

| 事实 | 存在哪 | 谁在用 |
|---|---|---|
| 素材属于室内还是室外、能放哪一层、碰撞口径 | `tools/asset-rules.mjs` 的 `ASSET_RULES` | 门禁、落位工具、审计 |
| **占几格**（逻辑尺寸，整数格） | `web/assets/manifest.json` 的 `foot` | 碰撞、重叠、落位求解 |
| **渲染缩放**（美术要放大/缩小到多大） | `web/assets/manifest.json` 的 `artScale` | 运行时渲染、桌面排布 |
| **台面高度**（桌面在贴图顶边往下多少像素） | `tools/asset-rules.mjs` 的 `SURFACE` | 桌面落位推导 |
| 物品在哪一格 | `web/map.json` 的 `x` / `y`（整数格 + 0.25 脚点偏移） | 渲染、碰撞 |

### 2.2b 大件家具必须按格子放大（这一条以前是缺的）

**旧规则**：`scale = min(1.15, cap×48 / 美术高)` —— 只看**高度**，宽度完全不受控，
而且放大被 1.15 倍锁死。实测结果：

| 素材 | 美术 | 旧渲染宽 | 折算格子 |
|---|---|---|---|
| 餐桌 | 58px | 55px | **1.14 格** |
| 沙发 | 46px | 53px | **1.10 格** |
| 双人床 | 28px | 32px | **0.67 格** |
| 衣柜 | 20px | 23px | **0.48 格** |

也就是说大件家具基本停在原美术尺寸，跟格子没关系。

**新规则**：素材声明 `foot: [宽格, 高格]`，`artScale` 由占格推导：

```
artScale = round(foot宽 × 48 × 0.92 / bbox宽)      // 内容宽 ≈ 占格宽的 92%
```

于是餐桌 `foot=[2,1]` → artScale 1.52 → 渲染 88px = 1.83 格；沙发同理；
衣柜 `foot=[1,1]` → 44px。**美术尺寸与逻辑尺寸彻底解耦。**

例外：**细高件**（路灯 / 更衣柜 / 文件柜 / 饮水机 / 落地灯 / 绿植 / 招牌 / 信箱 / 窗帘）
不按占格拉宽 —— 它们的画法本来就是"一根杆/一条缝"，拉宽会变成一块板。
它们仍声明 `foot` 用于碰撞。

### 2.2c 碰撞用整数占格，不用 bbox 投影

`cellsOf()` 的口径改成按 `ASSET_RULES[素材].body` 分流：

```
body = "none"  → 不产生碰撞（挂墙 / 桌上 / 纯装饰）
body = "cell"  → 只占主干 1 格（树 / 灌木 / 花：foot=[2,2] 指的是**树冠**，不是根部）
body = "full"  → 用 foot 声明的整数格（没声明才退回 bbox 投影）
```

以前全部按 bbox 底部投影算，70 个素材里 68 个落在半格上
（路灯 0.17 格、餐桌 1.21 格、橡树 2.00 格），判重叠时一直在跟小数打架。

**踩过的坑**：一开始让 `foot` 无差别优先，结果橡树 `foot=[2,2]` 占了 4 格，
一棵树把花园小径压断两格（门禁报 E1「路断了」）。所以 body 必须优先于 foot。

### 2.3 桌面物品的位置是**推导**出来的

```
dy = SURFACE[宿主素材]                   ← 量一次美术，写进素材库
dx = 按物品实际宽度装箱，整组居中          ← 自动排布，不出桌沿
```

排布算法（`tools/surface-fit.mjs`，门禁第 34 项守着，禁止手写 `dx/dy`）：

```
1. 取每件物品的**实际渲染宽度** = bbox宽 × sc
2. 若整组宽度 > 台面可用宽度 × 68%  → 按比例缩小 sc（下限 0.55，--scale 一次性动作）
3. 从 -total/2 起"贴着放"，每组中心落在台面中心
4. 一行仍放不下 → 分两排：最宽那件单独占后排（dy 抬高 5px），小件排前排
```

**为什么不能等分槽位**（第一版就是这么错的）：
它假设所有物品一样宽。实际笔记本 22px、果盘 30×0.7=21px、纸堆 20px。
两件物品中心相距 20px，但半宽之和 26px —— 必然被挤到左右边缘，
中间空一大块，看着像要掉下去（用户两次截图的直接来源）。

**为什么要按台面缩放**：餐桌面 58px，笔记本 + 果盘 = 45px，占 78%。
怎么排都会顶到桌沿，笔记本屏幕还会探出桌外。缩到 68% 之后左右各留 ~10px，
视觉上才读得出"摆在桌上"。

**为什么允许两排**：办公桌宽 42px，一台显示器就占 40px，三件并排几何无解
（实测 total 71px vs 可用 36px）。真实桌面本来就是显示器靠里、笔筒台灯在前。

### 2.4 台面高度怎么量（唯一需要人做的一步）

```bash
node tools/host-surface.mjs dining-table round-table kitchen-counter ...
# → logs/host-surfaces.png：每格 = 4 源像素，黄字是"距内容顶边多少像素"
# 肉眼看"桌面那条横线"的数值，填进 SURFACE 表
```

**注意**：不要用"最宽行"自动测量。实测会错——`kitchen-counter` 会被量成 1，
因为柜体后沿比台面更宽。台面是**美术语义**，必须看。

## 3. 当前落地的硬约束（全部是错误，不是警告）

门禁 `node tools/check.mjs`：

| # | 约束 | 判据 | 代码 |
|---|---|---|---|
| 33 | 分区 / 挂载层 / 碰撞重叠 / 素材分类 | 违规即错误 | `layout-check.mjs` + `map-model.layoutViolations()` |
| 34 | 桌面物品 `dx/dy` 必须等于推导值 | 手写即错误 | `surface-fit.mjs` |

`layoutViolations()` 的 8 类错误码：

```
E-UNKNOWN  素材没登记分类（无法判定 = 不许进场）
E-PLACE    室外件进了房间 / 室内件放到户外
E-LAYER    墙 / 地 / 桌 三层放错
E-TOP      只能放桌上的东西直接摆在了地上
E-HOST     桌上件引用的 host 不存在或不可承载
E-ANCHOR   桌上件缺 dx/dy（渲染位置全靠它）
E-OVERLAP  家具/设施互相重叠（植被之间豁免）
E-WALL     非挂墙件占了墙格
E-ROAD     落地件压在道路上
```

落位时同样硬拦：`node tools/place.mjs --id=X --cell=x,y` 会先过这套判据，
违规直接 `exit 1`（`--force` 可强行落盘，但门禁仍报错）。

## 4. 加新素材时必须做的三件事

```bash
# 1) 在 ASSET_RULES 登记 place / mount / body
# 2) 如果它能放东西，在 SURFACE 登记台面高度
node tools/host-surface.mjs <素材名>        # 出标尺图
# 3) 跑门禁
node tools/check.mjs                      # 34/34
```

漏第 1 步 → `E-UNKNOWN`；漏第 2 步 → `surface-fit.mjs` 报"跳过"，门禁第 34 项红。

## 5. 已知仍待改进

1. **碰撞格仍是 bbox 投影**，没有声明式整数占格（`foot: [w,h]`）。
   理想形态：每件素材声明占几格，与贴图尺寸解耦。当前靠 bbox 反推，
   所以 1.21 格这类结果还在。这是下一步该做的（最后一块结构性隐患）。
2. ~~等分槽位是线性的~~ → 已改为按实际宽度装箱 + 整组居中 + 自动缩放 + 两排兜底（见 §2.3）。
3. **台面高度靠人眼量**，还没有从美术导出时自动生成的能力。
4. **缩放后 `sc` 与别处不一致**：同一件素材在大桌上可能 1.0、在小桌上 0.7。
   当前可接受（桌面摆件本来就是相对尺寸），但如果要求"同一素材全局同尺寸"，
   应改为按素材固定尺寸 + 只允许两排/减少件数。
