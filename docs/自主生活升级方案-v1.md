# 自主生活升级方案 v1 —— 随机事件 / 小镇居民 / 数值系统

> 2026-11-07 · 目标：解决自由时间"套路化"，让 AI 的生活有起伏、有邻居、有可观察的内在状态。
> 原则：**前端只做表现层，大脑放 agent/hub**；所有新词条用一张数值表驱动，不为每个功能写 if/else。

---

## 0. 现状与问题

当前自由时间 = `LOCAL_EVENTS` 26 条静态小动作，按"距离加权 + 最近 6 条去重"抽取。
问题：

1. **无内在状态**：接水和瘫沙发权重永远一样，AI 不会"渴了才去接水"
2. **无随机性**：看过几天就能背出循环（接水→看月亮→翻书→瘫沙发…）
3. **无人际关系**：门廊挥手是挥给空气的，小镇只有一个居民
4. **无后果**：所有行为纯表演，不影响后续任何决策

## 1. 数值系统（新增"内在状态层"）

### 1.1 五项核心词条

| 词条 | 范围 | 驱动行为 | 恢复方式 | 衰减速率 |
|---|---|---|---|---|
| 饱食度 hunger | 0-100 | <30 觅食事件权重 ×5；<10 出现"饿晕"随机事件 | eating/snacking/dining | -1.2/小时，睡眠减半 |
| 心情 mood | 0-100 | 高→cheer/sing 系事件；低→发呆/听歌/找猫，气泡颜色变化 | 娱乐类事件 +3~8；error -15 | 缓慢回归均值 60 |
| 精力 energy | 0-100 | <25 强制犯困事件（打盹/回血）；影响走路速度 | sleeping/recovering/nap | -2.0/小时，重活加倍 |
| 社交 social | 0-100 | <30 找居民串门权重 ×4 | 与居民互动 +10/次 | -0.8/小时 |
| 卫生 hygiene | 0-100 | <35 洗漱/洗澡权重 ×3 | washing/洗澡 | -1.0/小时 |

### 1.2 存储与同步

- **真相源**：`office-hub` 内存 + `hub/state.json` 落盘（沿用现有持久化通道），字段 `stats: {hunger, mood, energy, social, hygiene, updatedAt}`
- **推送**：state 广播报文加 `stats` 字段；前端只读显示
- **更新**：hub 每 60s tick 一次衰减 + agent 每次任务结束钩子里加减
- **持久化跨重启**：`updatedAt` 补算离线衰减（上限：离线期间衰减到地板 15，不清零，避免"每次重启都饿死"）

### 1.3 前端表现（顶栏 + 气泡）

- 状态条新增一行"内在状态"：5 个小图标 + 迷你条（🍚😄⚡💬🫧），低于阈值闪橙光
- 气泡文案受数值影响：饱食度<30 → "有点饿了，去找点吃的…"（而非干巴巴的"吃饭"）
- 任务板新增一栏"今日生活记录"：随机事件流水

## 2. 随机事件系统（三层随机源）

### 2.1 事件分类

| 层 | 频率 | 举例 | 实现位置 |
|---|---|---|---|
| A 微随机（修饰） | 每次小动作都可能触发 | 接水时发现杯子没洗→顺路洗碗；翻书看到旧照片→心情+5 | 前端 LOCAL_EVENTS 加 `flavor` 字段池 |
| B 独立随机事件 | 每 2~6 小时一次 | 快递到了/停电/下雨忘记收衣服/网友投喂/猫来了 | **hub 定时器**决策，广播新 state |
| C 稀有大事件 | 每天 0~1 次 | 生日/纪念日/系统升级夜/断网一天 | agent 每日任务开头掷骰决定 |

### 2.2 B 层事件表（首批 12 条，存 `hub/random_events.json`）

| key | 内容 | 行为 | 数值影响 |
|---|---|---|---|
| delivery | 快递到了 | 走到门口签收，搬运 2 格 | 心情+6 |
| rain_sudden | 突然下雨 | 跑去花园收衣服（若之前晾了） | 心情-3，卫生+2 |
| cat_visit | 镇上的猫来了 | 追猫 10 秒，蹲下逗猫 | 心情+8，社交+4 |
| neighbor_knock | 邻居敲门借东西 | 开门对话 30s | 社交+10 |
| power_flicker | 停电一瞬 | 全屋灯闪，重新开灯 | 心情-2 |
| snack_craving | 嘴馋 | 直奔冰箱 | 饱食+8，卫生-2 |
| inspiration | 灵感突袭 | 冲向白板写写画画 | 心情+5 |
| phone_buzz | 手机震动 | 看手机，笑 | 社交+5 |
| plant_dry | 盆栽该浇水了 | 拿水壶浇花 | 心情+4 |
| bug_report | 线上出小 bug | 面色凝重回工位 | 心情-6，触发一次短 writing |
| memory_flash | 想起旧事 | 走到日记墙前驻足 | 心情+3 |
| market_day | 今日市集日 | 花园摊位进货，可买到新食材 | 饱食+10 |

- 触发机制：hub 内 `setInterval`（间隔 = 2h + rand*4h），从符合**时段/天气/数值条件**的池子里加权抽 1 条，转成一条 `{state:"event", eventKey}` 消息
- 前端收到后映射为一串编排好的动作序列（走到哪→播什么帧→气泡文案→数值回写），编排写在 `EVENT_SCRIPTS` 表

### 2.3 与天气/昼夜联动

- 雨天：outdoor 事件权重 ×3（看雨/踩水/收衣服），"出去散步"禁用
- 深夜（0-7 点）：只允许 indoor 安静事件（失眠/看月亮/热牛奶）
- 心情<25：禁止 high-cheer 类事件，增加"发呆""听雨"权重

## 3. 小镇与居民

### 3.1 视觉：新增第 5 个房间"小镇街道"（世界扩展 56→72 格）

- 布局：石板路 + 3 栋邻舍小屋（每栋 = 门 + 窗 + 屋主 NPC 的家）+ 街灯 ×2 + 布告栏
- 复用现有素材：house 类 / signpost / fence / street-lamp，必要时新下 2~3 件（house、bench、NPC 精灵）
- NPC 精灵：复用 whale 表的换色（hue shift 生成 3 个邻居：**橘猫·喵酱**、**水豚·村长**、**章鱼·博士**——各绑定 1 栋屋）

### 3.2 居民 NPC 行为循环（前端本地模拟，零后端成本）

- 每个 NPC 一个简单状态机：`在家 → 出门散步 → 在街灯下发呆 → 回家`，按真实时间表活动（村长早上浇花、博士下午遛弯、喵酱全天随机出没）
- 与鱼交互：鱼走到 NPC 附近 1.5 格内自动触发对话气泡（双方各一条），social+10
- 对话内容从 `NPC_DIALOGS` 表抽（每邻居 8~12 条，按时段/数值分档），例：
  - 喵酱：「喵？（今天已经吃了三条鱼干）」
  - 村长：「年轻人，早上好！今天市集有新到的果子。」
  - 博士：「我在想一个关于潮汐的问题…你问不到的。」

### 3.3 与 AI 的真实联动（可选渐进）

- **第一层（纯前端）**：上述模拟即可上线
- **第二层（hub）**：居民互动事件写入活动流（"14:32 · 和村长聊了天气"）
- **第三层（agent）**：agent 每日任务里随机抽一条"邻里事件"作为素材（如"喵酱今天抓了只蟑螂送来门口"），写进日记/周报——让小镇真正进入 AI 的"记忆"

## 4. 数值驱动的自由时间重排（解决"套路化"核心）

改造 `pickLocalEvent`：**权重 = 基础权重 × 需求系数 × 时段系数 × 天气系数 × 心情系数**

```
w' = w.base
   × hungerBoost(e)     // e.fills.hunger>0 时按饥饿度放大
   × moodBoost(e)       // 心情低→娱乐类放大；心情高→cheer 类放大
   × timeBoost(e)       // e.hours=[22,24] 之类时段窗
   × weatherBoost(e)    // outdoor 雨天 ×3 / 禁用
   × energyPenalty(e)   // 精力低→长途跨房间事件 ×0.5
   × curiosity(e)       // 随机扰动 ×(0.6~1.6)，保证同配置下两次选择不同
```

- 加"周记忆"：每条事件记 `lastSeenDaysAgo`，3 天内重复过的事件 ×0.4——**几天内不会走出同样的循环**
- 加"整点微事件"：每小时整点 5% 概率触发 A 层 flavor 事件（纯文案+1 个小动作）

## 6. 决策点（需要拍板）

1. **数值衰减速率**：按上表默认值先跑 3 天看日志再调？还是你直接给一组期望（比如"一天要吃 3 顿"）？
2. **NPC 数量**：首批 3 个居民够不够？要不要预留"访客"位（每周随机来一个新面孔）？
3. **B 层事件频率**：默认 2~6 小时一次偏保守（手机看不会一直错过），要不要加密到 1~3 小时？
4. **小镇世界扩展**：56→72 格会让单屏视野更小，是否接受？或改为"花园再往右延伸、街道占用花园下半"紧凑方案？
5. **agent 联动深度**：P4 的"居民进日记"要不要一起做（会让 AI 的日记更丰富，但改动 agent 主流程）？
